# Upstream contributions — owner runbook (Phases 2 and 3)

Target: [center-for-threat-informed-defense/attack-flow](https://github.com/center-for-threat-informed-defense/attack-flow)
(Apache-2.0). Pull requests target `main` and must pass the repository's tests. The project's
Developer's Certificate of Origin requires every commit to be signed off: `git commit -s`.
Nothing in this repository pushes to MITRE repositories; the owner opens the pull requests.

Phase 1 (this repository) is complete: the TLCTC source bundle, the extension, the converter and
the corpus study. Phase 2 makes TLCTC a selectable framework in the Builder. Phase 3 contributes
corpus flows that use it, and is gated on Phase 2 merging.

## Phase 2 — TLCTC as a framework source in the Builder

The Builder loads frameworks from STIX bundles listed in `src/attack_flow_builder/sources/sources.mjs`
and turns each into a generated enumeration file (ATLAS and F3 are the precedents). The TLCTC bundle
is served from this repository's `main`:

```
https://raw.githubusercontent.com/Barnes70/TLCTC/main/integrations/attack-flow/stix/tlctc-stix-bundle.json
```

Change set (all inside `src/attack_flow_builder/`):

Steps (the session may do everything up to the pull request under the owner's login):

```bash
gh repo fork center-for-threat-informed-defense/attack-flow --clone
cd attack-flow && git checkout -b tlctc-framework
cd src/attack_flow_builder && npm install
# apply the change set above
npm run update-tlctc                 # downloads the bundle, writes Tlctc.ts (10 tactics, 21 techniques)
npm run type-check && npm run test:unit && npm run lint
npm run dev                          # open the Builder, create an action, pick "[TLC] #7 Malware" / "[TLC] TLCTC-07.00 …"
cd ../.. && git add -A && git commit -s -m "builder: add TLCTC (Top Level Cyber Threat Clusters) as a TTP framework source"
git push -u origin tlctc-framework
```

**STOP here.** Pull request title: `Add TLCTC (Top Level Cyber Threat Clusters) as a framework source`. Body:

```
This adds TLCTC (Top Level Cyber Threat Clusters, https://www.tlctc.net) as a selectable TTP framework in the Builder, alongside ATT&CK, ATLAS, D3FEND and F3, using the same source mechanism (a STIX 2.1 bundle of x-mitre-tactic and attack-pattern objects, generated into an enumeration file by sources/update_stix_source.mjs).

TLCTC is a cause-oriented threat taxonomy: ten non-overlapping clusters, each defined by the generic vulnerability an attack step exploits, with outcomes kept separate. In the Builder's two-level slot the tactic holds the strategic cluster ("[TLC] #7 Malware") and the technique holds the operational position ("[TLC] TLCTC-07.00 Malware (vector unspecified)", or a published sub-cluster such as "TLCTC-02.10 Protocol vector"). Attack Flow says what the adversary did; TLCTC says which generic vulnerability each step exploited, which is what a defender needs to choose the control.

Changes: sources/sources.mjs (URL), sources/update_tlctc.mjs, "tlctc" in the accepted source names, prefix entries, the [TLC] framework entry and id regexes in TTPFrameworkConstants.ts, the import in SourceEnumeration.ts, the generated Tlctc.ts, an update-tlctc script, and a docs paragraph. Type-check, unit tests and lint pass.

The bundle is generated from the TLCTC v2.5 dictionary (names and definitions verbatim) and served from https://github.com/Barnes70/TLCTC/tree/main/integrations/attack-flow, which also holds a STIX property extension for TLCTC on attack-action and a study that classifies the 41 corpus flows through the ATT&CK→TLCTC mapping: https://github.com/Barnes70/TLCTC/blob/main/documentation/tlctc-attack-flow-corpus-study.md

Signed-off per the DCO.
```

If maintainers ask for changes to the bundle itself: edit the generator `scripts/build-attack-flow-stix.js` in the TLCTC repository, run `npm run build-attack-flow && npm run validate-attack-flow`, push to `main`, then `npm run update-tlctc` in the fork clone and push.

## Phase 3 — corpus flows with TLCTC classification (after Phase 2 merges)

1. Export two TLCTC attack paths to Attack Flow bundles:
   ```bash
   cd integrations/attack-flow
   python -m cli export ../../attack-paths/shai-hulud-worm-2025.json -o shai-hulud-worm-2025.attack-flow.json
   python -m cli export ../../attack-paths/chaos-muddywater-falseflag-2026.json -o chaos-muddywater-falseflag-2026.attack-flow.json
   ```
2. In a Builder built from the merged `main`: **Import STIX**, select the TLCTC framework on the flow (`Frameworks` property), and on each action pick the cluster the extension names (`tlctc_cluster` in the imported bundle; the Builder shows it in the action's description until the TTP is set). Add an ATT&CK technique alongside where the source names one.
3. Save as `.afb`, name the file after the incident, set `scope: incident`, fill `author` and the `external_references` from the path's `metadata.notes` sources.
4. One pull request per flow into `corpus/`, title `Add <incident> attack flow (TLCTC-classified)`, body: two sentences on the incident, the sources, and that every action carries both an ATT&CK technique and a TLCTC cluster. Sign off (`-s`).

## Not in scope of either phase

Tags with TLCTC colours, mitigations and detections on exported actions, an ATLAS→TLCTC mapping (the two OpenClaw corpus flows use ATLAS techniques, which the study reports as unmapped), and the AI-generation prompts. Each is a later offer.
