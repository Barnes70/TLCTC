# TLCTC v2.3 Core — Design Spec

**Date:** 2026-06-07
**Author:** Bernhard Kreinz
**Branch:** `v2.3-core` (off `main`)
**Status:** Approved design — ready for implementation plan

---

## 1. Background

TLCTC's framework content was finalized as v2.1 (transit `⇒`, intra-system `|[...]|`,
unresolved `?`/`…` operators, epistemic-state hierarchy), but the version signals have drifted:

- `json-schemas/layer-1/tlctc-framework.v2.0.json` carries `tlctc_version: "2.0"`
- `documentation/tlctc-v2.0-whitepaper.md` title block reads "Version 2.1"
- git tags go up to `v2.1.0` / `v2.1-golden`

A previously-planned **v2.2** consolidation freeze was never committed (no `v2.2-reconcile`
branch, no `v2.2.0` tag). The owner has decided to supersede that plan: cut a clean **v2.3
core** in new files, then clean up the rest in follow-on work. v2.3 is the version the
forthcoming Google-Scholar-indexable academic paper will cite.

## 2. Scope

### In scope
Two new files, authored **together** as a matched pair, forming the authoritative v2.3 core:

1. `json-schemas/layer-1/tlctc-framework.v2.3.json` — machine-readable core.
2. `documentation/tlctc-v2.3-core.md` — human-readable core paper.

### Out of scope (each a later, separate spec)
- Application doc (classification walkthroughs, decision trees, DRE usage, mapping *use*).
- Integration doc (SARIF, Sigma, MITRE/CWE mappings, tooling).
- Reconciling the old `2.0`/`2.1` version strings and git tags across the repo.
- Retiring / redirecting the old v2.0 files.
- The Scholar landing page, `citation_*` metadata, Zenodo DOI publication pipeline.

The old `tlctc-framework.v2.0.json` and `tlctc-v2.0-whitepaper.md` are **left untouched** by
this spec and coexist with the new v2.3 files until the cleanup spec.

## 3. Guiding principle (hard constraint)

**v2.3 is a consolidation, not an evolution.** Every cluster, axiom, and classification rule
in the new files MUST be traceable to existing finalized v2.1 content:

- Same 10 clusters, same 10 axioms, same R-* rules.
- Same v2.1 operators: transit `⇒`, intra-system `|[...]|`, unresolved `?`/`…`, epistemic states.
- **No new normative content.** If authoring reveals something that looks like it needs a new
  rule or definition, that is a **stop-and-flag** for the owner — never a quiet addition.

## 4. Artifact: `tlctc-framework.v2.3.json`

A faithful re-cut of the existing Layer-1 framework JSON with consolidated content.

- `tlctc_version: "2.3"` — content axis bumped.
- `schema_version: "2.0.0"` — **unchanged**. The JSON Schema *structure* is not changing,
  only content. (Three independent version axes: content / schema / tooling.)
- 10 clusters, 10 axioms, classification rules carried over verbatim-in-meaning from v2.1.
- v2.1 extension rules (R-TRANSIT-*, R-INTRA-*, R-UNRES-*) included so the core is self-complete.
- MUST validate against the existing Layer-1 JSON Schema.

## 5. Artifact: `tlctc-v2.3-core.md`

Self-contained core paper so the eventual PDF stands alone. Section structure:

1. Title / author / version / date / license (Scholar-friendly front matter)
2. Abstract + keywords
3. Introduction & problem statement (cause vs outcome ambiguity)
4. **The Thought Experiment** — logical derivation of the 10 clusters (from whitepaper §3)
5. Taxonomy design principles (non-overlap, cause-orientation)
6. The 10 clusters (canonical definitions)
7. The 10 axioms
8. Classification rules (R-* including v2.1 extensions)
9. Attack-path notation (operators, Δt velocity, boundaries, DRE, unresolved steps)
10. **Concise glossary** — only terms the paper uses (full `tlctc-glossary.md` stays separate
    as the exhaustive reference)
11. References

The paper **describes** the framework but does **not teach application** — no classification
walkthroughs or decision trees (those belong to the application doc). Cross-reference, don't
duplicate.

## 6. Workflow & isolation

- Work on branch `v2.3-core` off `main`. Worktree acceptable.
- **No `git push`, no merge to `main`, no PR, no tag-push** until the owner explicitly approves.
  Local commits are fine. Any `v2.3.0` tag is held locally too.
- **Sourcing method:** extract canonical definitions from `tlctc-v2.0-whitepaper.md` and
  `tlctc-framework.v2.0.json` (the finalized-v2.1 content); set the version strings to "2.3"
  **only in the new files**.

## 7. Acceptance criteria

1. `tlctc-framework.v2.3.json` validates against the Layer-1 JSON Schema.
2. Every cluster / axiom / rule in the new files maps to an existing v2.1 source — a short
   traceability note demonstrates consolidation, not invention.
3. The core paper is self-contained (abstract, references, concise glossary all present) and
   contains no application or integration material.
4. The old v2.0 files are untouched.
5. `tlctc_version` is "2.3"; `schema_version` remains "2.0.0".
